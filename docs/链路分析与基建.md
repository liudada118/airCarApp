> 全部对照仓库里的真实文件，不空谈。

## 一、现在整条链路怎么协作（真实文件版）

```
┌── Android 原生 (Kotlin) ───────────────────────────────────────────────┐
│                                                                        │
│  USB串口(CH340)                                                         │
│    │ 读字节                                                             │
│  SerialManager.kt ── 起线程 ──> SerialReadThread.kt (断线重试5次)        │
│    │ 原始字节                                                           │
│  ByteRingBuffer.kt (环形缓冲，找帧尾 AA5503 99)                          │
│    │                                                                    │
│  FrameParser.kt ──> FrameResult(csv, length)  按长度分帧                 │
│    │                                                                    │
│  SerialModule.kt  ★上帝模块：串口+算法+气囊指令+阈值+Python 全在这        │
│    ├─ 144B 传感器帧 ─> 算法层(见下) ─> onSerialData / onSerialResult 事件 │
│    ├─ 51B  模式帧   ─> onSerialMode 事件                                 │
│    └─ 其它  非标帧   ─> onNonStandardFrame 事件                          │
│                                                                        │
│  算法层【双轨并存！】                                                    │
│    ├─(旧) Python/Chaquopy: server.py → integrated_system.py (release_pkg)│
│    └─(新) C/JNI: AirbagNative.kt → libairbag.so (airbag_13Hz, 179维输出) │
│                                                                        │
│  写指令: SerialModule.startAutoWrite(15Hz) / sendAirbagCommand           │
│          ─> SerialManager.writeBytes ─> 55B 气囊帧 ─> 串口               │
└────────────────────────────────────────────────────────────────────────┘
        │ NativeEventEmitter 事件(data=CSV字符串 / result=JSON字符串)
        ▼
┌── React Native (JS/TS) ─────────────────────────────────────────────────┐
│  HomeScreen.tsx  监听事件 → useState(sensorData/realtimeData) → 重渲染     │
│    ├─ CarAirRN.js (Three.js/expo-gl 3D压力云图)                          │
│    ├─ SeatFront.tsx / SeatMatrix46 / AirbagHeatmap (座椅&热力图)          │
│    ├─ CustomAirbagScreen.tsx (手动气囊调节 → sendAirbagCommand)           │
│    └─ VoiceBar + voicePlayer (小可语音，已解耦得不错)                     │
│  配置持久化: SharedPreferences(airbag_thresholds) + AsyncStorage          │
└──────────────────────────────────────────────────────────────────────────┘
```

**协作要点**：原生侧是"数据生产者"(读串口→解析→算法→发事件)，JS 侧是"消费者"(收事件→存状态→渲染)。
写指令是反向：JS 触发 → SerialModule 拼 55B 帧 → 串口。二者靠 `@ReactMethod`(JS调原生) + 事件(原生推JS) 两个通道协作。

## 二、逐环节：现在怎么做 + 怎么优化

| 环节 | 现在怎么做（真实文件） | 主要问题 | 怎么优化 |
|---|---|---|---|
| **① 传输** | `SerialManager`/`SerialReadThread`/`SerialEnumModule`，USB 串口 + 重试线程 | 只绑死 USB 串口；波特率靠手配 | 抽 **Transport 接口**(串口/蓝牙/TCP 可换)；**波特率自动扫描**(脑图已列)；连接**状态机统一** |
| **② 协议解析** | `FrameParser` 按长度硬分支(144/51/其它)，`ByteRingBuffer` 找帧尾 | 帧格式**写死在代码**；换产品要改代码；无校验 | **帧格式配置化**(帧描述表：长度/帧尾/单元字节)；加**校验和**；多帧类型由配置驱动 |
| **③ 算法** | **双轨并存**：Python/Chaquopy(旧) + C/JNI `AirbagNative`(新)；阈值可运行时改存 SharedPreferences | 两套并存最乱；文档还写 Python；`SerialModule` 里两边都调 | **定一条主线**(C/JNI)，砍掉/隔离 Python；**算法插件接口统一**(init/step/setThreshold)；输出契约固定(179维) |
| **④ Native↔JS 桥** | `SerialModule` 一个类管全部；数据走 **CSV/JSON 字符串**事件 | 上帝模块职责过载；字符串**解析开销大**、无类型 | **拆模块**(Transport/Algo/Airbag 各一个，已拆出 `AirbagModule`)；高频数据改**二进制/TypedArray** 过桥；事件**类型化** |
| **⑤ 状态/渲染** | `HomeScreen` 事件→useState→重渲染；渲染组件多而散(`CarAirRN.js`/`AirHomeRN.js`/`AirAsideRN.js`/`SeatFront`/`SeatMatrix46`/`AirbagHeatmap`)，js/tsx 混 | 无集中数据源；高频 setState 卡；组件重复 | 引入**数据仓库 store**(集中最新帧+派生指标，组件订阅)；高频渲染**脱离 setState**(ref+rAF/Skia，VoiceBar 已实践)；统一**"压力场"数据契约**喂所有可视化组件；组件去重 |
| **⑥ 数据业务** | 基本没有；`mockSerialData` 是**静态帧**且按 Python 输出建模 | 无采集/回放；调试必插硬件 | **录制/回放**(真实帧存盘可回放)；mock 升级成**录播源**；采集→导出 |
| **⑦ 观测/配置/文档**(横切) | 埋点无；配置散在 SharedPreferences + AsyncStorage；`ARCHITECTURE.md` 过时 | 配置多处易冲突(你被覆盖默认值坑过)；文档漂移 | **统一配置层**(出厂默认/可运行时改/只读 三档)；**统一埋点**(点击+丢帧率+坏点率)；文档减少漂移 |

> 三个"现在最该先处理"的：**③算法双轨**(定主线)、**④上帝模块拆分 + 别用字符串过桥**、**⑥录制回放**。

## 三、基建：该建哪些库（util / ui / …）

按"越底层越先建、复用率越高"排序：

### 1. `util` 纯函数库（★最先建，无 React/RN，可单测、可跑 Node）
把散在各处的纯逻辑收进来——**这类最好抽、最好测、AI 改完能自动验证对错**：
- 帧解析(FrameParser 的纯逻辑部分)、字节工具、校验和
- 点位映射 / 线序 / 坏点处理
- 插值取值(`sample`)、派生指标(**COP / 左右平衡 / 舒适度**，demo 已跑通)
- 颜色映射(色阶，425 那个默认值收这里)
- 录播编解码

### 2. `hooks` 库（RN 侧，把"取数据"封装掉）
`useDeviceConnection` / `useFrameStream` / `usePressureField` / `useAlgoOutput` / `useRecorder`

### 3. `viz` 可视化组件库（跨产品直接复用）
`<HeatCloud>` `<BodyOverlay>`(最实用) + `<Contour>` `<Terrain3D>` `<Bars3D>` `<Particles>` `<TimelineReplay>` `<ZoneDashboard>` `<ColorScaleLegend>`
> `demos/pressure-viz.html` 就是这一层的效果预研。

### 4. `ui` 通用组件库（你已有不少，沉淀即可）
现成可沉淀：`Modal`/`Toast`/`TopBar`/`ConfirmModal`/`ConnectionErrorModal`/`theme`(colors/spacing)。
新增：**阈值配置面板**(已有雏形)、**标定向导**(单点按压学点位序)、`AirbagController`/`MassageController`。

### 5. `core` 设备层（无 UI）
Transport 抽象、协议解析(配置驱动)、算法插件接口、store、事件总线。

### 6. `profiles` 配置库
每个产品一份 Device Profile(座椅/睡眠垫…)。

**现状可直接沉淀的资产**：`ByteRingBuffer`、`FrameParser`、`AirbagNative`、`mockSerialData`、`VoiceBar`(解耦好)、`theme/`。

## 四、Monorepo：规范 & 怎么做

### 为什么用
终结"一个产品一条分支复制整套代码"。公共代码一份，各产品是**薄壳 app**。你已经有 `pnpm-lock.yaml`，用 **pnpm workspace** 最顺。

### 目录规范
```
airCar-platform/
├── packages/
│   ├── util/        纯函数(帧/插值/指标/颜色/校验)  —— 不依赖 react-native
│   ├── core/        transport / codec / 算法接口 / store —— 无 UI
│   ├── hooks/       RN hooks(useFrameStream…)
│   ├── viz/         可视化组件(HeatCloud/BodyOverlay…)
│   ├── ui/          通用UI(Modal/Toast/TopBar/配置面板)
│   ├── types/       跨包类型契约(Frame/DeviceProfile/AlgoOutput)
│   └── profiles/    各产品配置(seat.json / sleep.json)
├── apps/
│   ├── seat/            座椅 app(薄壳：装配 profile + 选组件 + native)
│   └── sleep-monitor/   睡眠垫 app(薄壳)
├── native/          共享原生(串口Kotlin / 各算法.so)，按 profile 选择加载
├── package.json     workspaces 声明
├── pnpm-workspace.yaml
└── tsconfig.base.json / .eslintrc / .prettierrc  根配置，各包继承
```

### 必须定的规范（重点）
1. **依赖方向单向、不许成环**：`apps → hooks/viz/ui → core → util/types`。
   `util`/`types` 是最底层，**谁都能依赖它，它不依赖任何人**。
2. **`util`/`core` 禁止 import `react-native`**：保证能在 Node 单测、能跨端(RN/Web)复用。
   （这条是能不能自动化测试、AI 能不能自动验证的关键红线。）
3. **类型即契约**：`Frame`/`DeviceProfile`/`AlgoOutput` 放 `types` 包，改实现不改契约。
4. **包内互相引用用 `workspace:*`**：本地直接链，不发 npm。
5. **根配置统一**：一份 `tsconfig.base` / eslint / prettier，各包 extends，风格一致。
6. **分支/协作规范**：主干开发 + **短命功能分支**；**产品差异走 `profiles`，不再靠拉长期分支**。
   （直接根治远端 `CARMain`/`sleep-monitor`/一堆人名分支那套。）
7. **CI 规范**：改 `util`/`core` → 跑全量单测(用**录播数据**，脱硬件)；各 app 独立打包。
8. **原生代码**：座椅 C 算法/Kotlin 放 `native` 或对应 app，用 profile 决定加载哪个 `.so`。

### 怎么做（渐进迁移，Strangler，不推倒重来）
| 步 | 动作 | 风险 |
|---|---|---|
| 1 | 建 `packages/util`，把纯函数(插值/指标/颜色/帧解析JS部分)搬进去，app 引用 | 低 |
| 2 | 建 `core`+`hooks`，把事件订阅封装成 `useFrameStream` 等 | 低 |
| 3 | `viz` 抽 1–2 个组件(HeatCloud/BodyOverlay) | 低 |
| 4 | 正式 `pnpm-workspace.yaml` 化，`apps/seat` 变薄壳 | 中 |
| 5 | 复制 `apps/sleep-monitor` 验证复用(只写新 profile + 挑组件) | 中 |

> **先只动 JS 侧做 monorepo**(收益高风险低)；原生(串口/算法)先不动，等 JS 侧跑顺再抽 `native` 包。

## 附：一句话优先级
**③ 算法定主线(砍 Python 双轨) → ④ 拆上帝模块 SerialModule + 别用字符串过桥 → ⑥ 录制回放 → 建 util 库 → pnpm workspace 化。**
先做 `util` 库 + 录制回放这两件：既是地基，又能立刻脱硬件开发、让 AI 帮你改代码时能自动验证。
