# UI 设计交付规范（MasterGo）

给设计师看的。按这份规范出图，设计稿改完在代码侧跑一条命令就能同步，**不用开发再手抄一遍色值和字号**。

不按这份规范也能出图，只是同步不了——开发还得照着标注一个个抄，改一次抄一次。

适用于所有要接这套管线的项目，不限于座椅项目。

---

## 一、核心原则：给样式起名字

这是整份规范里唯一真正重要的一条。

代码里同步的不是"颜色"，是**"名字 → 值"的映射**：

```
颜色/主色  →  #2978CE
```

设计师把主色从 `#2978CE` 改成 `#1A6FC4`，名字没变，代码这边一条命令全应用生效。

但如果设计稿里只是散着填了 `#2978CE`，代码这边看到的就是一个孤零零的色值。改成别的色，**没有任何东西能对应上**——因为它从来就没有身份。

所以：**凡是会复用的颜色、文字规格，都要建成"样式"，不要直接填色。**

## 二、必须做的三件事

### 1. 建颜色样式

选中图形 → 右侧填充 → 点样式图标 → 「创建样式」。

命名用 `/` 分层，这会直接变成代码里的结构：

```
颜色/主色              →  Colors.primary
颜色/文字/主要          →  Colors.textPrimary
颜色/文字/次要          →  Colors.textSecondary
颜色/状态/成功          →  Colors.statusSuccess
颜色/背景/卡片          →  Colors.bgCard
```

**建议直接用英文命名**（`Color/Primary`、`Text/Secondary`），代码 key 会自动转成 `primary`、`textSecondary`，比中文名干净。中文也能用，只是 key 会是 `颜色主色` 这种。

渐变同理，也建成样式：`渐变/按钮主色`、`渐变/开关底轨`。

> ⚠️ 千万别用 `1` `2` `11` `2222` `路径 12` 这种默认名。当前这个座椅项目就是这样，
> 生成到代码里是 `Gradients._1`、`Gradients._2222`，谁都不知道是什么，只能人工一个个认。

### 2. 建文字样式

选中文本 → 右侧文本面板 → 「创建样式」。一套样式包含字号、行高、字重。

```
文字/标题              →  Typography.title
文字/正文              →  Typography.body
文字/说明              →  Typography.caption
文字/按钮              →  Typography.button
```

**行高一定要填具体数值，别用「自动」。** 自动行高在不同字体下渲染结果不同，代码侧拿不到确定值，只能退回系统默认，最终效果和设计稿对不上。

### 3. 画板尺寸对齐真机，且全项目统一

**同一个项目里所有页面用同一个画板宽度**，并且这个宽度尽量对齐目标设备的实际逻辑分辨率。

原因：设计稿的 px 和设备上的显示尺寸未必是一回事。如果画板宽度和真机逻辑宽度不一致，
设计稿上标 22px 的字，到设备上看着就不是那个大小——开发只能凭感觉调，调完设计稿再改又对不上。

**画板宽度 = 真机逻辑宽度**的话，设计稿标多少代码写多少，全程不用换算，这是最省事的做法。

对不齐也不是不能做，但那就成了开发侧要处理的问题（等比缩放、或者按设计比例重新标一遍），
**多一道人为环节就多一处出错的地方**。所以开工前定画板尺寸时，先问一句目标设备是多少。

画板宽度混用（有的 1920 有的 1440）是最糟的情况，怎么处理都不对。

## 三、建议做的

### 圆角和间距收敛到有限几个值

MasterGo 没有"圆角样式""间距样式"这种东西，代码侧只能扫画布统计出现频次。

所以圆角别 8、9、10、12、13 乱用，收敛成 `4 / 8 / 12 / 16 / 24` 几档；间距同理。
值越集中，统计出来的规范越可信。

### 图标统一放一个页面，用组件

图标做成组件（Component），命名规范些（`icon/seat/heat`），代码侧可以批量导 SVG。
散落在各页面的矢量图形不好批量处理。

### 一个页面 = 一个顶层 Frame

不要把多个页面塞进一个 Frame，也不要让页面元素散在画布上没有父容器。
代码侧按 Frame 识别"一屏"，这直接影响能不能整页生成代码。

### 用自动布局（Auto Layout）

用了自动布局，间距是 `itemSpacing` 这样的结构化数据，代码侧能直接读成 flex 布局。
纯手工摆位置的话，代码侧只能拿到绝对坐标，还原出来的布局换个屏就崩。

## 四、不用管的

- **切图导出**：不用手动切，开发用插件/MCP 直接导
- **标注**：不用标，代码侧直接读数据
- **写文档说明色值字号**：不用写，样式名就是文档

## 五、自查清单

出图交付前对一遍：

- [ ] 左侧「样式」面板里，颜色样式数量 > 0
- [ ] 左侧「样式」面板里，文字样式数量 > 0
- [ ] 样式名有意义，不是 `1` `2` `矩形 3` 这种默认名
- [ ] 样式名用 `/` 分了层
- [ ] 文字样式的行高是具体数值，不是「自动」
- [ ] 所有页面画板同宽，且开工前确认过和目标设备分辨率一致
- [ ] 每个页面都在一个顶层 Frame 里
- [ ] 圆角/间距收敛在几个固定档位

前两条不满足的话，这套管线基本用不上——开发还是得手抄。

## 六、开发侧对应操作

设计交付后：

```bash
# 1. MasterGo 里跑插件「Design Token 导出器」→ 复制到剪贴板
# 2.
cd c:\project\airCarApp\airCarApp
npm run sync:design
```

插件面板会报出画板尺寸，接新项目时对一眼是不是和目标设备一致。

详见 [design/README.md](../design/README.md)。

## 七、如果设计稿已经画完了，没建样式怎么办

不用推倒重来，两条路：

1. **补建样式**（推荐）：插件会生成 [design/design-usage.md](../design/design-usage.md)，
   里面按出现次数列出了设计稿实际用到的所有色值和字号。出现次数高的就是事实上的规范，
   照着在 MasterGo 里建成样式即可，不用重画。

2. **在代码侧起名**（过渡方案）：在 [design/token-map.json](../design/token-map.json) 的
   `usageColors` 里给色值起名：

   ```json
   {"usageColors": {"#2978CE": "primary", "#FFFFFF": "textPrimary"}}
   ```

   字号不用配，插件扫到的会自动生成 `FontSize.fs22` 这样的 token。

   **但这只是过渡**：映射的键是色值本身，设计师一改色，映射就失配、要人工更新。
   样式库的名字挂在设计稿里，改色值名字不变，那才是真正的自动同步。
