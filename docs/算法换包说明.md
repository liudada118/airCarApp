# 算法换包说明（给算法团队）

> 从现在起，换算法**不用再找 App 那边重新打 APK**。
> 你把新的 C 包编成 `libairbag.so`、推到平板、重启 App，App 会自动优先加载你这个新包。

---

## 〇、从「C 包做好」到「换好」——完整流程

你手上是 Simulink 生成的一套 C 文件（`airbag_13Hz.c/.h`、`rt_nonfinite.*`、`rtGetNaN.*`、`rtwtypes.h` 等）。三步：

```
① 把新 C 文件放进 android/app/src/main/c_airbag/   （覆盖旧的同名文件）
② 编译：  bash android/app/src/main/cpp/build_so.sh        → 生成 libairbag.so
③ 推送：  ./scripts/push-algo.sh android/app/src/main/jniLibs/arm64-v8a/libairbag.so
```

第②步 `build_so.sh` 会把你的 `c_airbag/*.c` 和 App 侧的 JNI 胶水 `cpp/airbag_jni.c`
一起编成 `arm64-v8a/libairbag.so`。第③步推到平板并重启，就换好了。

**一次性准备（每台电脑只做一次）：**
- 装 Android NDK（r27 附近，和 App 侧一致），设环境变量指向它：
  `export ANDROID_NDK=/你的/Android/Sdk/ndk/27.1.12297006`（Windows 用 `/c/Users/...` 形式）
- 装 `adb`（Android platform-tools），平板 USB 连电脑或开无线调试。
- 拿到本仓库（至少 `android/app/src/main/{c_airbag,cpp}` + `scripts/push-algo.sh`）。

> 如果你只想交一个编好的 `libairbag.so`、不想碰仓库：那就只做第③步，
> 把 `push-algo.sh` 后面换成你那个 `.so` 的路径即可（见下面「一」）。

---

## 一、只有 .so 时的最简操作（三步）

平板用 USB 连上电脑（或 `adb connect 平板IP:端口` 无线连上），然后：

**方式 A：用脚本（推荐，一条命令搞定）**

```bash
./scripts/push-algo.sh  你编好的/libairbag.so
```

脚本会自动：推包 → 重启 App → 提示你怎么确认生效。

**方式 B：不用脚本，纯 adb 三条命令**

```bash
# 1. 推到 App 的私有目录（目录名固定 algo，文件名固定 libairbag.so）
adb push libairbag.so /sdcard/Android/data/com.awesomeprojectgpt/files/algo/libairbag.so

# 2. 关掉 App
adb shell am force-stop com.awesomeprojectgpt

# 3. 重新打开 App（也可以手动点图标）
adb shell monkey -p com.awesomeprojectgpt -c android.intent.category.LAUNCHER 1
```

就这样。重启后 App 就跑你的新算法了。

---

## 二、怎么确认换成功了

App 一启动加载算法时会打一行日志。看：

```bash
adb logcat -s AirbagNative
```

- 看到 `已加载算法覆盖包 -> override:...` → **你的新包生效了** ✅
- 看到 `已加载内置算法包` → 没找到你的包，还在用打包内置的（检查路径/文件名对不对）

---

## 三、想还原成 App 内置的老包

删掉你推的文件、再重启 App 即可：

```bash
adb shell rm /sdcard/Android/data/com.awesomeprojectgpt/files/algo/libairbag.so
adb shell am force-stop com.awesomeprojectgpt
```

---

## 四、换包必须守住的约定（很重要，破坏了会崩）

App 是按**固定的名字和数据格式**去调你的 `.so` 的。你内部算法随便改，但下面这些**不能变**：

| 项 | 约定值 | 说明 |
|---|---|---|
| 文件名 | `libairbag.so` | 推上去必须叫这个名 |
| CPU 架构 | `arm64-v8a` | 用同一套 NDK 编，跟现在一致 |
| JNI 导出符号 | `Java_com_awesomeprojectgpt_airbag_AirbagNative_native*` | **即使你 C 侧改了包名/加了 `_v2` 后缀，导出给 App 的这组 JNI 函数名也必须保持这个前缀不变**（对应 App 里的 `com.awesomeprojectgpt.airbag.AirbagNative`） |
| 入口函数 | `nativeInitialize()` / `nativeStep(...)` / `nativeTerminate()` | 函数签名不能改 |
| 输入 | `nativeStep` 收 **92 字节**压力 | 帧点数别改 |
| 输出 | `FloatArray`，长度 **283**，且各下标含义不变 | 布局见 `AirbagNative.kt` 顶部注释（reasonCode/frame[55]/热力图/健康位…） |
| 阈值表 | `nativeThresholdCount/Name/...SetThreshold` 这组保留 | 配置面板靠它运行时调参 |

> 一句话：**算法逻辑随便改，但「函数名 + 92进283出的格式」不能动。** 要加新输出字段，先跟 App 侧对齐，在末尾追加、别插在中间。

**⚠️ Simulink 出码特别注意：模型名保持 `airbag_13Hz`。**
JNI 胶水 `cpp/airbag_jni.c` 直接引用 Simulink 生成的全局量 `airbag_13Hz_U / _Y` 和函数
`airbag_13Hz_step()/_initialize()/_terminate()`。如果你改了模型名或加了 `_v2` 之类后缀，
这些名字会跟着变，第②步 `build_so.sh` 就会编译报错。改名了必须同步告诉 App 侧改胶水。
输入/输出字段（`frame_data1`、`frontCmd1`、`reasonCode1`… 见 `airbag_jni.c`）名字也要保持一致。

---

## 五、原理（一句话）

App 启动加载算法时，会先去 `Android/data/.../files/algo/libairbag.so` 找你的覆盖包：
找到就用你的、没找到就用打包内置的。所以你推一个新包上去、重启，就换好了——不碰 APK。
